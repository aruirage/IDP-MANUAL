NeosAI IDP マニュアル

NeosAI IDP は、保険金請求などの業務書類を対象に、アップロードされた資料を案件単位で集約し、AI-OCR、業務ルール、AI検証、人工確認を組み合わせて処理する Intelligent Document Processing システムです。

管理者が事前に設定したルールに基づき、複数種類の帳票を自動分類・読取・検証し、業務担当者は 案件一覧 と マイタスク で確認・修正・出力処理を行います。

処理全体の流れ

admin 側で処理ルールを定義し、業務操作側では公開済みの設定に基づいて案件処理を進めます。エクスポート結果の確認や出力操作は マイタスク 内で実施します。

ルール設定モジュール

保険金請求のケースに沿って、推奨順序は モデル → API → マスターデータ → 帳票タイプ → 業務シーン → データマッピング → AI検証 です。

各画面への到達順：モデル設定 → API設定 → マスターデータ設定 → 帳票タイプ設定 → 業務シーン設定 → データマッピング設定 → AI検証設定。各機能モジュールの操作手順と、画面だけでは分かりにくい適用タイミングを説明します。ロール詳細は ロール設定 を参照してください。

ルール設定モジュール

モデル設定

本モジュールでは、NeosAI IDP で利用するモデルリソースを一元管理します。OCR抽出、AI検証、データマッピングで使うモデルを、用途ごとに割り当てて管理します。

機能説明

権限：本機能は admin が設定します。操作員はモデル接続や用途割当を編集せず、公開済みの業務シーンを通じて割当済みモデルの処理結果を利用します。

設定ロジック：API 接続 では外部モデルプロバイダへの接続情報を登録し、用途割当 では機能ごとに使用するモデルを指定します。OCR抽出 のみ複数モデルを選択でき、主モデルの認識結果を検証するために使用します。その他の用途は 1 用途につき 1 モデルを選択します。

OCR抽出帳票タイプ設定、OCR確認複数モデル帳票画像から項目や表の内容を読み取り、認識結果を作成します。モデル間の結果比較にも使用します。
AI検証AI検証設定1 モデル必須項目、必要書類、整合性、テキスト、データ、署名・印鑑を確認します。

利用タイミング：OCR 抽出、AI 検証、データマッピングで使うモデルを、用途ごとに先に登録・割当しておきます。保険金請求では、診断書や診療明細書の読取、請求内容の整合性確認、出力データの変換処理で参照されます。

画面操作

1業務ルール設定 → モデル設定 を開き、API 接続 タブで登録済みの接続を確認します。新規登録する場合は + 接続を追加 をクリックします。

保存後、接続テストを実施して初めてステータスが有効となり、当該モデルを利用可能になります。

2接続を追加 画面で プロバイダ、API ベース URL、API キー、モデル名、状態 を設定し、保存 します。プロバイダに独自エンドポイントを使用する場合は カスタム (OpenAI 互換) を選択します。

3用途割当 タブで用途ごとにモデルを割り当てます。OCR抽出 は複数モデル、その他の用途は 1 モデルを選択します。

ルール設定モジュール

API設定

本章では、外部システムから NeosAI IDP を呼び出すための Open API を管理します。設定画面は 通知先URL、APIキー管理、API URL の 3 タブです。パス、フィールド英語名、エラーコードは専用の API 接続文書を参照してください。

機能説明

権限：本機能は admin が設定します。操作員は API 設定を編集せず、画面操作または公開済み業務シーンに基づく処理結果を利用します。

設定ロジック：APIキー管理 では外部システムが使う API キーを発行・管理します。通知先URL では、プラットフォームが外部へ送るコールバック先と 署名鍵 を設定します。API URL では、ファイルアップロード、案件一覧照会、バッチ別案件照会、追加資料アップロード、一括エクスポート、エクスポートタスク照会のエンドポイントを確認し、コピーできます。

利用タイミング：画面から手動アップロードする代わりに、社内システムや RPA から案件投入、進捗照会、補件、一括出力を行う場合に利用します。リクエストは API キーで認証します。

画面操作

1業務ルール設定 → API設定 を開き、APIキー管理 で登録済みの API キーと有効状態を確認します。新規発行する場合は +API キー をクリックします。

2+API キー のダイアログで 名称 を入力し、有効期限 を 7日間 / 1年 / 3年 から選択して発行します。

3通知先URL タブで 外部通知設定 を確認します。通知先URL と 署名鍵 を変更する場合は 編集 をクリックします。

4編集画面で 通知先URL を入力します。署名鍵 は 生成 で発行し、保存 します。

5API URL タブで、ファイルアップロード、案件一覧照会、バッチ別案件照会、追加資料アップロード、一括エクスポート、エクスポートタスク照会のエンドポイントを確認します。コピーアイコンで URL を取得できます。リクエスト形式などの詳細は専用の API 接続文書を参照してください。

影響先影響内容
新規アップロードAPI の ファイルアップロード は画面と同じく、公開済みの 業務シーン を必須とし、帳票分類と案件集約を起動します。形式・サイズ・解像度の検証も画面アップロードと同じです。API の 追加資料アップロード は 案件一覧 の補件直付けと同じで、案件番号を指定し、案件ステータスが 補件 のときだけ対象案件へ直接書き込みます（案件集約は経由しません）。

マイタスクAPI の 一括エクスポート は、業務シーンの出力ルールに従います。データ量が多い場合は非同期になり、エクスポートタスク照会 で進捗とダウンロード先を取得します。画面側のエクスポートタスクは マイタスク で処理します。
業務シーン設定ファイルアップロードで指定できるのは公開済みシーンのみです。出力形式は業務シーンの出力設定に従います。通知先URL への外部コールバックは、少なくともエクスポート完了時、および案件が 処理完了 または エクスポート済 になったときに送ります。業務シーン Step3 の操作端通知とは別経路です。
注意事項 無効、期限切れ、または停止中の API キーでは外部システムから呼び出せません。通知先URL の保存時は 署名鍵 が必須です。署名鍵を再生成すると既存の外部受信側の検証が失敗するため、連携先と同時に更新してください。案件が補件不可・エクスポート不可のときは API も拒否します。リクエスト形式、認証方式、エラーコードは専用の API 接続文書を参照してください。

ルール設定モジュール

マスターデータ設定

本章では、OCR で読み取った値を業務で利用できる標準名称やコードへ変換するためのマスターデータを管理します。医療機関名、傷病名、薬剤名、銀行名、支店名など、表記ゆれや略称が発生しやすい項目をマスター表として登録します。

ここで作成したマスター表、列設定、照会コード、登録データ、ベクトル化状態は、帳票タイプ設定の処理ルールから マスタ照合 として参照されます。

機能説明

権限：本機能は admin が設定します。操作員はマスターデータを編集せず、OCR 確認画面で照合結果や候補値を確認・選択します。

参照元：マスタ照合 で参照するデータは、本章で登録したマスター表です。列設定で定義した列名、照会コード の有無、登録済みデータ、ベクトル化状態 がそのまま照合に利用されます。

セル単位の照合：帳票タイプ設定でグループを指定しない場合、対象項目の OCR 値だけを使ってマスター表を検索します。例：診断書の 傷病名 を傷病名マスターに照合し、表記ゆれを標準傷病名へ寄せます。

グループ単位の照合：複数項目に同じグループ番号を設定した場合、それらの OCR 値を組み合わせて 1 回の照合条件として扱います。例：銀行名 と 支店名 を同じグループにし、銀行・支店マスターを行単位で照合します。

検索・返却の方針：照会コード が設定された列がある場合は、コード系の値による完全一致・優先一致を試みます。該当がない場合は、対象列に対して表記ゆれを考慮した類似検索を行います。候補が一意に確定できる場合は、命中したマスター行の標準値やコードを返却します。

画面操作

1業務ルール設定 → マスターデータ設定 を開き、+ マスター追加 でマスター表を作成します（例：医薬品情報、銀行情報）。

2列設定 でマスター表の列を定義します。コード検索や完全一致を優先したい列には 照会コード を設定します。例：ICD10 コード、銀行コード、支店コード。

3大量データは 一括インポート からテンプレートをダウンロードし、Excel / CSV ファイルでまとめて登録します。更新方式は 追加更新 または 上書更新 を選択します。1 回のインポートは最大 50,000 行です。

4少量のデータは + 項目追加 で 1 行ずつ登録します。登録済みデータは行内編集・削除・再ベクトル化でメンテナンスします。登録後は一覧の ベクトル化状態 を確認し、完了 になったデータからマスタ照合に利用します。

関連影響

影響先影響内容
帳票タイプ設定処理ルール設定 で マスタ照合 を選択した項目は、本章で登録したマスター表、列設定、照会コード、ベクトル化状態を参照します。
OCR 確認候補が複数、類似度が低い、または未命中の場合は自動確定せず、OCR 確認タスクで人工確認の対象になります。
業務シーン設定OCR 抽出後の項目に対して、業務シーンで設定したマスタ照合が適用されます。ベクトル化未完了のデータは照合候補として利用できません。
注意事項 1 万行規模以上の大量データでは、ベクトル化に 30 分以上かかる場合があります。インポート直後に業務設定へ進む場合は、ベクトル化完了を待ってから帳票タイプ設定側で効果テストを行ってください。状態が 失敗 の行は、再ベクトル化で手動リトライできます。

ルール設定モジュール

帳票タイプ設定

本章では、業務で扱う帳票ごとに、分類条件、読取項目、後処理ルール、画像処理方法を定義します。ここで設定した内容は、アップロード後の帳票分類、案件集約時のファイル整理、OCR 抽出、人工確認、出力確認に反映されます。帳票間を 1 件の案件としてまとめるルールは業務シーン Step1 で設定します。

保険金請求では、請求書、診断書、診療明細書などを帳票タイプとして登録し、それぞれの帳票から読み取る項目や表格列を設定します。帳票ごとの特徴を明確にしておくことで、後続の業務シーンで正しい帳票を選択し、安定した処理フローを構成できます。

機能説明

権限：本機能は admin が設定します。操作員は帳票タイプそのものを編集せず、公開済みの業務シーンを通じて設定結果を利用します。

生成 AI による柔軟性の高い帳票抽出の可視化設定機能です。帳票タイプは次の 5 ステップで設定します。

設定何を決めるか反映先
AI分類設定 代表サンプル、説明文（AI 分類基準）、ファイル分割ルール を定義します。説明文は帳票タイプ判定、分割ルールは同一ファイル内の帳票切り分けに使います。 新規アップロード後の帳票分類、混在ファイルの論理分割、業務シーンで選択する帳票タイプ候補。
AI読取設定 OCR 抽出で読み取る項目・表格列・プロンプト・正解サンプル・読取モデルを定義します。 ワークフローの OCR 抽出 ノード、条件分岐、データマッピング、AI 検証、マイタスクの OCR 確認画面。
処理ルール設定 OCR 値の後処理、マスタ照合、信頼度閾値を定義します。 OCR 抽出後の値補正・標準化、低信頼度・未照合時の人工確認判定。
画像処理設定 画像分割、同一帳票タイプ内のファイル組合、画像整列、OCR 実行単位を定義します。 案件集約時の論理ファイル判定、OCR 抽出前の画像整理、同一帳票タイプ内ファイルの組合。
効果テスト サンプル画像で分類・抽出・処理ルール・画像処理の結果を確認します。 業務シーンへ組み込む前の事前検証。

画面操作

1タイプ追加 と AI分類設定：帳票タイプ設定 で + タイプ追加 し、帳票名 を付けて代表サンプルをアップロードします。説明文（分類基準）と ファイル分割ルール を記入します。例：診断書 の説明文を「医療機関が発行する診断書」とし、分割ルールを「ページ番号の連続性が途切れる位置で分割」にします。

2AI読取設定：保存アイコンから テンプレートをダウンロード し、項目を記入して 一括インポート します。プロンプトと正解サンプルはテンプレートで手書きしても、項目名だけ入れて次の手順の AI自動生成 に任せても構いません。

3必要に応じて AI自動生成 でプロンプトと正解サンプルを生成し、内容を確認・微調整します。

4設定アイコンから 読取モデル設定（メイン／検証モデル）と エクスポート設定（ファイル名・文字コード）を行います。

5処理ルール設定：各項目に日付整形・数値整形・マスタ照合などの後処理を割り当てます。AIマッチング で一括提案もできます。

マスタ照合の設定 参照元は マスターデータ設定 で登録済みのマスター表です。マスタ照合 を選ぶと マスターデータ の選択欄が表示され、表名と照合対象列を指定します。列構成と 照会コード はマスター表側の 列設定 で定義した内容がそのまま使われます。表が未登録の場合は選択候補が空となり、保存できません。

照合単位（セル照合 / グループ照合） グループ を空欄にした項目は、当該項目の OCR 値だけをマスター表に照会します。グループ に同じ番号を入力した複数項目は、OCR 値を組み合わせて 1 回の照合クエリとして扱います。例：振込先金融機関名・振込先支店名をともに グループ 1 に設定し、銀行・支店マスターへ同時照合します。

マッチング戦略と返却 ハイブリッド検索 で表記ゆれを許容しつつ類似候補を取得し、コード照会 では 照会コード 列による完全一致も試みます。照合成功時は、命中したマスター行の正規値を当該項目へ書き戻します。類似度が 自信度 閾値を下回る、候補が複数、または未命中の場合は書き戻さず要確認となり、OCR 確認タスクの対象になります。

ルール設定モジュール

業務シーン設定

業務シーン設定では、アップロード後の案件をどのように集約し、どのノード順で処理し、いつ通知し、何を出力するかをまとめて定義します。ここで公開した設定だけが新規案件に使われます。

本マニュアルでは 保険金請求 を例に、Step1 案件集約、Step2 ワークフロー、Step3 通知、Step4 出力・公開 の順で説明します。

機能説明

権限：admin と業務ルール設定権限を持つユーザーが編集します。操作員は公開済みの業務シーンだけを利用します。

設定の考え方：Step1 で案件集約条件を決め、Step2 で導入時に設定済みのワークフローを確認し、Step3 で通知ルールを決め、Step4 で出力項目と公開版を決めます。Step1 の 関連チェック に成功した場合のみ 次へ で Step2 へ進め、成功時は内容が自動保存されます。Step2 の 設定チェック は構成確認のみで、実案件は動かしません。チェックに通ると公開可能になり、公開 後は新規案件がその版を参照します。

Step何を決めるか下流への影響
Step1 案件集約関連帳票、主帳票、業務キー、帳票間の関連項目。関連項目が一致すると帳票間に関連が生じます。グループ内は AND、グループ間は OR。関連チェック 通過後に Step2 へ進行。案件一覧の集約結果、新規アップロード時の集約判定。
Step2 ワークフローキャンバスでのノード編成・接続・設定チェック。各ノードの対象 ON/OFF と分岐条件。ルール本体は帳票タイプ／データマッピング／AI 検証と連携。案件の処理順、マイタスクの起票、再処理・補件の経路。
Step3 通知どのノードのどのイベントで、誰へ通知するか。件名・本文は変数プールから変数を選んで自由に作成します。トリガーイベント発生時に、設定した宛先へサイト内メッセージが自動送信されます。
Step4 出力・公開出力項目と公開対象の確定。マイタスクのエクスポート内容、新規案件が参照する公開版。

本製品の導入時には、業務シーンごとに案件集約・ワークフロー・通知・出力項目などがあらかじめ設定された状態で提供されます。お客様は通常、内容を確認し、必要に応じて調整するだけで構いません。

Step2 キャンバスの操作

Step2 では、案件集約後の処理順をノードで編成します。導入時にワークフローが設定済みのため、通常は確認・微調整が中心です。キャンバスでは次ができます。

  • ノードの追加・配置：右下の ノード追加、またはノード一覧から前処理・OCR・データマッピング・AI 検証などを追加し、ドラッグで配置します。
  • 接続の編成：ノード間を線でつなぎ、処理順と分岐先を決めます。開始 から 終了 まで到達できる必要があります。
  • 左下の編集ツールバー：左から 元に戻す / やり直し / 変更履歴（この画面を開いている間のみ保持）/ 削除（開始ノード以外を一括削除。確認ダイアログあり）。
  • 右下のツールバー：左から ノード追加 / 拡大 / 縮小 / 整列・適応サイズ（ノード配置を整え、全ノードが画面に収まるよう表示を合わせる）。
  • 設定チェック：終了到達・分岐出口・必須 ON 項目などを静的検証し、通過すると 公開可能 になります（テスト案件は実行しません）。

8通知：対象ノード・トリガー・通知先を設定し、件名・本文は変数プールから変数を選んで作成します。イベント発生時にサイト内メッセージが自動送信されます。

ルール設定モジュール

データマッピング設定

本章では、複数の帳票タイプから抽出された OCR 項目を、案件単位で利用する標準変数へ整理します。保険金請求では、被保険者名、医療機関名、請求金額、証券番号などが複数帳票にまたがるため、同じ意味の項目を 1 つの標準変数として扱えるようにします。

機能説明

権限：本機能は admin が設定します。操作員はマッピングルールを編集せず、公開済みの業務シーン内でマッピング後の値を確認・利用します。

用途：帳票タイプごとに異なる項目名や値の形式を、業務で使う共通項目へそろえるために使用します。例：保険金請求書の 被保険者氏名 と診断書の 患者氏名 を、標準変数 被保険者名 へまとめます。マッピングルールは、業務シーンの Step1～Step2 を設定した後、当該業務シーン向けに登録します。

実行ロジック：データマッピングは、業務シーン設定 のワークフロー内に配置された データマッピング ノードで実行されます。OCR 抽出後の値、処理ルール適用後の値、マスタ照合後の標準値を参照し、設定された標準変数へ変換します。

画面操作

1業務ルール設定 → データマッピング設定 を開き、マッピングルール生成 で 標準変数、表示名、参照元の 帳票タイプ と フィールド を選択します。必要に応じて 標準化ルール を入力し、追加 します。

2複数帳票から同じ意味の項目を集約する場合は、マッピング一覧 の 編集 から ソースフィールド を追加します。値の表記や形式をそろえる必要がある場合は 標準化ルール を確認・調整して OK します。

3AIルール最適化 を使用すると、標準化ルールの候補を生成できます。生成結果はそのまま確定せず、保険金請求の業務表現や後続出力形式に合わせて確認・修正します。

業務シーン設定データマッピングは、ワークフロー内の データマッピング ノードで実行されます。ノードが配置されていない場合、マッピング設定は実行されません。
AI検証設定標準変数に複数の参照元がある場合、標準データ整合性 で一致確認の対象にできます。
出力項目マッピング後の標準変数は、業務シーン設定の出力候補として利用されます。
注意事項 データマッピングは値を標準変数へ整理する機能です。項目の競合や業務上の整合性判定は、AI 検証設定で扱います。

ルール設定モジュール

AI検証設定

本章では、OCR 抽出結果や案件内の帳票構成を AI で検証するためのルールを設定します。保険金請求では、必須フィールド、必要書類、標準データ整合性、テキスト検証、データ検証、署名・印鑑検証の 6 モジュールで確認します。

機能説明

権限：本機能は admin が設定します。操作員は AI 検証ルールを編集せず、マイタスク で検証結果を確認・修正します。

実行ロジック：AI 検証ルールは、業務シーン設定 のワークフロー内に配置された AI検証 ノードで実行されます。業務シーンの Step1～Step2 を設定したうえで AI検証設定 にルールを登録し、業務シーン側の AI 検証ノードで対象の検証種別を ON にすると実行対象になります。

検証モジュール確認する内容ルール例保険金請求での例
必須フィールド指定した項目が空欄ではないかを確認します。対象項目が未入力の場合は要確認にする。請求番号、被保険者名、診断日、請求金額が入力されているか。
必要書類案件に必要な帳票タイプが提出されているかを確認します。必須帳票が存在しない場合は不足書類として扱う。保険金請求書、診断書、診療明細書がそろっているか。
標準データ整合性マッピング済みの標準変数どうしの値が一致しているかを確認します。比較対象の標準変数が異なる場合は不整合にする。請求書の被保険者氏名と診断書の患者氏名が一致しているか。
テキスト検証自然文ルールに基づき、自由記述や長文項目の妥当性を確認します。{{診断書・医療機関名}} と {{診療明細書・診療機関名}} の名称が完全一致していること。帳票間の医療機関名が一致しているか。
データ検証数値、日付、期間、合計などの構造化データを確認します。{{入院・通院・手術状況報告書・今回のご請求の入院期間起期}} <= {{入院・通院・手術状況報告書・今回のご請求の入院期間止期}}入院期間の開始日が終了日以前であるか。
署名・印鑑検証対象帳票に署名または印影が存在するかを確認します。対象帳票の指定領域または全文から署名・印影の有無を検出する。請求書の署名欄、医師の押印欄、同意書の署名有無。

画面操作

1必須フィールド — ルール一括追加 で 適用シーン、帳票タイプ、フィールド を選び、挿入 で 選択フィールド に追加して 追加 します。標準変数を対象にする場合は 標準フィールド を はい に切り替えます。追加後は ルール一覧 に反映され、行の 削除 で無効化できます。

2必要書類 — 業務シーン を選び、案件に必要な帳票タイプを 必須 または 任意 に設定します。保険金請求では、診断書・保険金請求書・診療明細書などの提出有無を案件単位で確認します。

3標準データ整合性 — データマッピング設定 で参照元が 2 件以上ある標準変数が一覧表示されます。データ整合性検証 スイッチを ON にすると、同一標準変数に紐づく OCR 値の一致を検証します。マッピング自体はデータマッピング設定で編集します。

4テキスト検証 — ルール追加 で 適用シーン、ルール名、ルール記述 を設定します。フィールド参照は 挿入 で {{帳票タイプ.フィールド名}} 形式のトークンを書き込み、少なくとも 1 件の有効なフィールド参照が必要です。必要に応じて AIルール最適化 を使い、ルール一覧 の 編集 で内容を更新します。

5データ検証 — 数値・日付・期間・合計などの構造化データを、算術式または自然文 + フィールドトークンで検証します。入院期間、請求日、点数合計など、帳票間の整合性確認に使います。AIルール最適化 で式の整理も可能です。

6署名・印鑑検証 — 適用シーン、ルール名、対象帳票、検出対象（印影／署名／両方）、必要に応じて 照合先 を設定して 追加 します。各ルールは 状態 スイッチで個別に ON/OFF できます。

業務操作モジュール

業務操作モジュール

公開済みの業務シーン（本マニュアルでは 保険金請求）を前提に、資料アップロードから案件確認、マイタスク での人工確認・出力までを説明します。

業務操作モジュール

新規アップロード

本章では、公開済みの業務シーンを選択し、保険金請求に関する資料をアップロードして案件処理を開始します。新規アップロードは、帳票分類と案件集約を実行する入口です。

機能説明

権限：本機能は admin、操作員、操作管理者、または該当メニュー権限を持つユーザーが利用します。

利用シーン：新しい保険金請求案件を開始する場合に使用します。請求書、診断書、診療明細書などをまとめてアップロードし、公開済みの 業務シーン に基づいて帳票分類と案件集約を行います。

処理ロジック：分類・案件集約を実行 をクリックすると、アップロード済みの合格ファイルを対象に、帳票分類と案件集約が順に実行されます。帳票タイプ設定の分類説明と、業務シーン設定の案件集約条件が参照されます。

3 つの資料追加経路：新規案件の開始は 新規アップロード（新規集約経路）。既存案件への補件は、案件一覧 からの直付けと、新規アップロード からの集約の 2 通りがあります。

経路入口前提処理
新規集約経路 新規アップロード 公開済み 業務シーン を選択 帳票分類 → 案件集約 → 案件一覧 へ反映
補件・直付け経路 案件一覧 · 補件 案件ステータスが 補件（マイタスク で審査員が補件を選択した後など） 対象案件に直接書き込み。分類・集約は経由しない
補件・集約経路 新規アップロード 公開済み 業務シーン を選択（案件番号は不要） 新規集約と同様に分類・案件集約を実行。関連キーが 補件 状態の案件に一致すれば優先的に紐付け。未自動归属のファイルは 未集約ファイル に残る

画面操作

1新規集約経路 — サイドバーの 新規アップロード を開き、業務シーン を選択したうえで、ファイル選択、フォルダ選択、ZIP 選択、またはドラッグ＆ドロップで資料を追加します（JPG / PNG / TIF / PDF、各 50MB まで）。アップロード済ファイル 一覧で取込結果を確認し、選択した業務シーンに対して 分類・案件集約を実行 すると、一覧内のすべての合格ファイルを一括処理します（一括削除 は選択行のみ、集約は一部選択では実行されません）。

2分類・案件集約が完了すると、案件一覧 の 未集約ファイル タブへ遷移します。自動で案件にまとまったファイルは 集約済み案件 タブで確認でき、自動集約できなかったファイルは 未集約ファイル に残ります。未集約ファイルは 新規アップロード から再度集約を実行するか、案件一覧 で手動紐付けを行います。

3補件・直付け経路 — 案件一覧 · 集約済み案件 で、案件ステータスが 補件 の行の 補件 をクリックします（補件アップロード API も同じ経路。案件番号は必須）。書類追加アップロード ダイアログは対象案件 ID に固定され、業務シーン の選択欄は表示されません。ファイルを追加して アップロード確定 すると当該案件へ直接書き込まれます（形式・50MB 上限は新規集約経路と同じ）。

4補件・集約経路 — 案件番号が分からない場合は、新規アップロード と同じ手順で公開済み 業務シーン を選び、補件書類を追加して 分類・案件集約を実行 します。関連キーが 補件 状態の既存案件に一致すれば優先的に紐付けられ、一致しなかったファイルは 未集約ファイル に残ります（Step 2 と同様に手動紐付けまたは再実行）。

業務操作モジュール

案件一覧

本モジュールでは、案件の集約状態、配下ファイル、詳細プレビュー、ワークフロー進捗、操作ダイアログを順に確認します。保険金請求では、集約済み案件 で進行中案件を把握し、展開後のファイル、詳細画面、担当者割当、ファイルの案件変更、未集約ファイルの手動紐付けまでを確認します。

機能説明

権限：admin、操作員、操作管理者、または該当メニュー権限を持つユーザーが利用。処理中止 は 操作員 も可。割当（案件担当者改派）は 操作管理者・admin のみ。案件担当者は最初の人工確認ノードの指派先ロールから自動指名されますが、操作管理者 がここで手動改派することも可能（改派後、未完了タスク担当者も同期更新）。

利用シーン：アップロード後に案件へ集約された資料、または自動集約できなかった未集約ファイルを確認します。保険金請求では、案件単位で提出書類、配下ファイル、担当者、処理ステータス、ワークフロー進捗を確認します。

確認ロジック：集約済み案件 では、案件単位にまとまったファイルと進捗を確認します。未集約ファイル では、分類または案件集約に失敗したファイルを確認し、再集約または手動紐付けを行います。

画面操作

1集約済み案件 タブで、案件 ID、業務シーン、業務 key、作成日時、更新日時、ファイル数、入力済書類、案件ステータス、担当者を確認します。案件 ID または 詳細 から詳細画面へ進めます。上部の検索条件で絞り込み、すべて展開 で配下ファイルを一括表示できます。

2案件行を展開すると、配下ファイルのファイル名、帳票タイプ、アップロード日時、更新日時、帳票枚数、ファイルサイズ、ファイルステータスを確認できます。各行の プレビュー、案件変更、削除 でファイル単位の操作が可能です。案件行では 詳細、割当、処理中止、削除 が利用できます。

3案件 ID または 詳細 から詳細画面を開き、ファイル一覧 タブで帳票タイプ別のツリーと画像プレビューを確認します。プレビュー上のツールバーで拡大・回転ができ、不要ファイルは 削除 で除去できます。

4ワークフロー明細 タブでは、処理フロー で本案件の経路（実線）と未採用分岐（点線）を確認し、経過ノード で各ノードの開始・完了日時と担当者、ファイル処理明細 でファイル単位の OCR 進捗を確認します。

5割当 で 案件担当者 を改派（操作管理者 のみ）。処理中止 でワークフローを終了し未完了タスクを無効化（操作員・操作管理者、確認ダイアログで OK）。

6展開後のファイル行で 案件変更 をクリックし、帳票タイプ・関連 key・紐付け先案件を指定して別案件へ移動します。分類失敗などで誤った案件に紐付いたファイルの修正に使います。

7未集約ファイル タブでは、自動集約に失敗したファイル（集約ステータス 紐づけ失敗、失敗理由など）を確認します。案件集約を実行 で再処理するか、手動紐付け で 手動校正 ダイアログを開き、帳票タイプと紐付け先案件を指定します。

業務操作モジュール

マイタスク

本章では、ワークフローから起票された作業を確認し、割当先のロールまたは担当者が必要な確認・修正・出力を行います。マイタスクは、人工確認とエクスポートの実行入口です。admin は全体権限として本章の機能も利用できます。

機能説明

権限：該当ロールまたは担当者に表示。操作員は 対応 のみ、割当 は操作管理者・admin のみ（案件一覧 の改派とは独立）。人工確認ノードの指派先は操作員・操作管理者のみ選択可能で、最初の人工確認ノードで選択したロールから案件担当者が自動指名されます。以降同じロールの人工確認ノードは同一担当者が継続処理し、ロール切替時に新ロールから再指名されます。

処理対象：本画面では OCR 抽出確認、AI 検証確認、エクスポート の 3 種類のタスクを扱います。前処理確認タスクは本期対象外です。

タスク種別発生する場面担当者が行うこと完了後の動き
OCR 抽出確認OCR 値の信頼度が低い、モデル間で結果が一致しない、マスタ照合の候補が確定できない場合。帳票画像と抽出値を照合し、テキスト・テーブル・マスタ候補を確認、必要に応じて修正します。OCR 抽出完了 で後続ノードへ進みます。補件または案件中止を選択することもできます。
AI 検証確認AI 検証ノード実行後、1 件以上の検証ルールが 確認待ち となった場合（必須フィールド不足、必要書類不足、標準データ不整合、テキスト検証 NG、データ検証 NG、署名・印影不足など）。AI 検証要約結果 で当該案件の実行済み検証ルールをすべて確認します。緑の 確認済み は確認済みのルール、青の 確認待ち は人工確認対象です。要確認ルールについて判定理由・対象帳票・フィールドを確認し、確認済み・補件・案件中止を選択します。AI 検証完了 で後続ノードへ進みます。補件時は案件一覧から追加書類を受け付けます。
エクスポートワークフローの確認処理が完了し、出力可能になった場合。業務シーン設定の出力項目に沿って内容を確認し、結果を提出します。提出後、案件は エクスポート済 として扱われます。

画面操作

1未対応 / 対応済 でタスクを切り替え、タスク種別・案件キー・業務シーン・業務 key で絞り込みます。未対応行の 対応 で実行ページへ進みます。

2OCR 抽出確認：一覧の 対応 から実行画面を開き、左の帳票プレビューと右の テキスト読取 / テーブル情報読取 で抽出値を確認・修正します。項目位置を非表示 を ON にすると切り出し画像と帳票上の対応領域が連動します。マスタ照合フィールドでは 類似度検索 候補から正規値を選べます。確認後、フッターの OCR 抽出完了 で後続ノードへ進みます。

人工確認ノードとの連動（OCR / AI 検証共通） 実行画面フッターの OCR 抽出完了 / AI 検証完了 は、ワークフローキャンバス上の 人工確認 ノードの 完了 出口に対応し、後続ノードへ進みます。前処理の人工確認タスクは本期対象外です。補件 は 補件 出口へルーティングされ、キャンバスで設定した前段ノード（例：OCR 抽出）へ戻ります。案件は 補件 状態となり、案件一覧 から追加書類をアップロードします。案件中止 はキャンバス上では接続せず、選択時に現在のワークフローインスタンスを終了します（案件自体は再実行可能）。保存 は進捗のみ保存し、出口は確定しません。

3AI 検証確認：AI 検証要約結果 タブで実行済み検証ルールを確認します。緑の 確認済み は確認済みのルール、青の 確認待ち は人工確認対象です。必須フィールド・必要書類・標準データ整合性・テキスト検証・データ検証・署名・印鑑検証 ごとに判定理由と対象帳票を確認し、問題なければ 確認済み に更新します。すべて処理したら AI 検証完了 で後続ノードへ進みます。

4エクスポート：出力形式（CSV / JSON / EXCEL）を選び、左の エクスポート対象 ツリーと右のプレビューで出力内容を確認します。処理結果をエクスポート で結果ファイルを出力し、必要に応じて 前処理済み ZIP を取得したうえで エクスポート完了 をクリックします。

5割当 でタスク担当者を変更（操作管理者のみ）。
